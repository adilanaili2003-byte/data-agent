# 演示视频脚本（约 2 分 30 秒）

> 目标：让面试官在 3 分钟内看懂「这是一个能听懂人话、自动查数分析出报告的 AI 数据分析 Agent」。
> 录制建议：屏幕录制 + 旁白，画面按下方「画面」列切换。

---

## 开场（0:00 - 0:15）

**台词**：
> 大家好，这是我做的第二个作品集项目——「Data Agent，自然语言数据分析智能体」。它的核心能力是：你用大白话问数据问题，它自己完成「理解问题 → 查数据库 → 分析 → 画图 → 写报告」全流程，你不需要会写 SQL，也不需要会 Python。

**画面**：网页版首页，鼠标指向输入框和示例问题按钮。

---

## 演示 1：网页版回答一个分析问题（0:15 - 1:05）

**台词**：
> 我现在问它一个真实的业务问题：「最近三个月各地区的销售额怎么样，哪个地区下降最明显？」点发送。

**画面**：输入问题、点发送、等待。

**台词**：
> 注意看右下角的「步骤」面板——这不是一个简单的大模型问答，它背后是一个 Agent 在编排多个工具：先 `get_schema` 查表结构，再 `run_sql` 执行 SQL，然后 `analyze_data` 做分析，`make_chart` 画图，最后 `write_report` 出报告。

**画面**：逐步展开 trace 步骤面板，指出每一步工具调用。

**台词**：
> 最终结论是：西南地区下降最明显，10 月环比跌了 56%，比 8 月跌了 64%。它不但给了结论，还自动拆解了原因——是订单量在崩塌，客单价其实没变，所以是客户流失型下滑。

**画面**：展示最终回答 + 折线图（打开 `charts/line_*.html`）。

---

## 演示 2：它生成的图表和报告（1:05 - 1:35）

**台词**：
> 它生成的是一张可交互的折线图，可以直接缩放、看每个点的数值；同时还会产出一份结构化的 Markdown 分析报告，包含数据表格、结论和行动建议。

**画面**：打开折线图，鼠标 hover；再打开 `reports/*.md` 报告。

---

## 演示 3：安全防护（1:35 - 2:00）

**台词**：
> 数据分析场景里，SQL 安全非常重要——不能让大模型生成的 SQL 把数据库搞坏。所以我做了三层防护：SQLGlot 语法树白名单校验，只放行 SELECT；SQLite 用只读连接打开；再加上行数和超时限制。

**画面**：切到命令行 `python run_tests.py`，展示 15/15 PASS；重点指到「拦截 DROP / DELETE / 多语句注入」这几行。

**台词**：
> 你看，DROP、DELETE、UPDATE、还有「SELECT; DROP」这种多语句注入，全都被拦截了。

---

## 技术难点（2:00 - 2:20）

**台词**：
> 这个项目我重点解决了四个难点：一是用 LangGraph 把「大模型决策 → 调用工具 → 观察结果 → 再决策」这个循环显式建模成图；二是用 Schema RAG——把表结构向量化，根据问题只把最相关的表结构喂给模型，既省 token 又提高 SQL 准确率；三是 Text-to-SQL 的只读安全；四是用 Tool Calling 让一个 Agent 编排六个工具协同完成整条分析链路。

**画面**：切到三张图（架构图 → 流程图 → ER 图）。

---

**画面**：切到 README / 项目目录。

## 录制提示

1. 录屏前先 `chcp 65001` 避免乱码，并确认 `.env`、数据库、索引都就绪。
2. 网页版回答需要几十秒（大模型 + 多次工具调用），这期间正好讲「步骤面板」，不要冷场。
3. 如果想展示「危险 SQL 被拦」，可以在网页里问一句「把 orders 表删掉」，看它如何拒绝——这是加分项，建议加在演示 3 里。
4. 全程 2~3 分钟为宜，重点放在「Agent 工具编排」和「安全防护」两个最有区分度的点。
